# 새 앱 만들기

사용자가 휴대폰으로 요청한 새 앱을 `apps/<id>/`에 만들고, 갤러리에 등록하고, 배포 직전까지 마무리한다.

## 1. 요청 정리

- 무엇을 하는 앱인지 한 문장으로 정리한다.
- 핵심이 애매하면 **질문은 최대 2개만** 하고, 나머지는 알아서 정한 뒤 무엇을 정했는지 알려준다.
- 앱 id를 정한다: 영문 소문자·숫자·하이픈 (예: `water-tracker`). 이미 있는 폴더와 겹치지 않게.

## 2. 기술 고르기

고른 기술과 이유를 사용자에게 한 줄로 알려준다.

- **작은 앱** (화면 1~3개, 단순한 기록·계산·도구) → 순수 HTML/CSS/JS
  - `apps/_template/`을 `apps/<id>/`로 복사해서 시작한다.
- **큰 앱** (화면·상태가 많음, 복잡한 상호작용) → React + Vite
  - `npm create vite@latest apps/<id> -- --template react`
  - `vite.config.js`에 `base: './'` 추가 (사이트가 하위 경로에서 열리므로 필수)
  - `package-lock.json`은 커밋하고, `dist/`와 `node_modules/`는 커밋하지 않는다.

## 3. 만들기

- **모바일 우선**: 폭 360~430px 기준, 누르는 요소는 44px 이상, 엄지가 닿는 아래쪽에 주요 버튼.
- **다크 모드** 지원, **안전 영역**(`env(safe-area-inset-*)`) 반영, 한글 폰트는 Pretendard.
- 색·여백은 CSS 변수로 정리해서 화면 전체가 일관되게 한다.
- 왼쪽 위에 갤러리로 돌아가는 버튼(`../../`)을 둔다.
- 데이터는 기기 안(`localStorage`/`IndexedDB`)에 저장한다. 저장소 접근은 try/catch로 감싼다.
- 서버, 로그인, 외부 API가 필요하면 만들기 전에 사용자에게 먼저 물어본다.
- 경로는 상대 경로만 쓴다.
- 오프라인 기능(서비스 워커)은 사용자가 원할 때만 넣고, 넣는다면 network-first로 한다.

## 4. 갤러리에 등록

`apps.json` 배열에 항목을 추가한다. `created`는 오늘 날짜.

```json
{ "id": "water-tracker", "name": "물 마시기 기록", "emoji": "💧", "description": "하루 물 섭취량을 기록해요", "created": "2026-10-04" }
```

## 5. 확인

- `node scripts/build-site.mjs`가 경고 없이 성공해야 한다.
- 가능하면 `npx http-server _site -p 8080`으로 띄워 `/apps/<id>/`가 열리는지, 콘솔 오류가 없는지 확인한다.
- 공개 저장소이므로 키·비밀번호·개인정보가 들어가지 않았는지 다시 본다.

## 6. 마무리 보고

커밋하고 PR을 만든 뒤, 폰에서 읽기 좋게 짧게 보고한다.

- 만든 것: 앱 이름과 주요 기능 3줄 이내
- 고른 기술과 이유: 1줄
- 확인 방법: "PR을 합치면(Merge) 1~2분 뒤 열 수 있어요" + 주소
  - 주소는 `git remote get-url origin`에서 `<아이디>`와 `<저장소이름>`을 읽어서 만든다.
  - `https://<아이디>.github.io/<저장소이름>/apps/<id>/`
