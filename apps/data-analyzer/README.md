# 데이터 분석기 (범용 회귀·배치·수지 분석)

시간별 순시값을 넣으면 회귀식을 찾고, 엑셀(순시값·그래프·함수설명)과 **예측용 모델 파일(JSON)** 을 만든다.
특정 공정 전용이 아니라 여러 분야의 시계열·반복 작업·입출고 기록에 쓰도록 만들었다. 예시 데이터는 제강(가스 회수·홀더), 화학(반응기 배치), 설비(물탱크) 등이다.
나중에 만들 예측 앱의 기반이 되도록 계산 부분과 화면 부분을 나눠 두었다.

| 화면 | 하는 일 | 예 |
|---|---|---|
| 측정값 | 시간 변화·항목 관계 회귀, 다중 회귀, 조작 판단 학습 | 온도·압력 기록, 운전 기록 |
| 배치별 | 반복 작업(배치·사이클·로트·회차)마다 총량·평균·최고값 비교, 대표 곡선, 중간 예측, 조건과의 관계 | 강번별 가스 회수량, 사이클별 전력량, 반응기 온도 곡선 |
| 수지 | 유입·유출 계측값과 저장량(레벨)으로 수지를 맞춰 계측기별 편차·계측 안 되는 손실 찾기 | 가스 홀더, 물탱크, 사일로, 배터리 |

## 표 읽기 (`reader.js`)

- 엑셀(.xlsx, 시트 선택 가능), CSV(UTF-8·EUC-KR), 붙여넣기(탭·쉼표·세미콜론·공백)를 읽는다.
- **방향 자동 판별**: 항목이 열(세로)인지 행(가로)인지 점수로 판단한다.
  점수 기준: 첫 줄이 이름(글자)인가, 나머지 칸이 숫자인가, 첫 칸이 시간처럼 늘어나는가, 값 개수가 항목 수보다 많은가. 화면에서 직접 바꿀 수도 있다.
- 칸이 듬성듬성한 위쪽 제목·설명 줄, 아래쪽 메모 줄, 완전히 빈 열은 뺀다.
- 이름 아래 단위 줄(°C, kW)이나 2단 머리글(병합 셀)은 `온도 (°C)`, `온도 외기`처럼 이름에 붙인다.

## 분석 방법

- **시간에 따른 변화**: 항목마다 `y = f(t)`
- **항목 관계**: 「가장 궁금한 값」 y와 다른 항목 x 하나씩 `y = f(x)`, 그리고 상관계수 표
- **다중 선형 회귀**: `y = b0 + Σ bj·xj`
- 함수 후보는 직선, 지수(`a·e^(bx)`), 로그(`a + b·ln x`), 거듭제곱(`a·x^b`), 2차, 3차다.
  지수·로그·거듭제곱은 로그를 취해 직선으로 바꿔서 맞춘다. 그래서 R²는 원래 값 기준으로 따로 계산한다.
- 자동 선택: AICc(작은 표본 보정 AIC)가 최솟값과 2 이내인 함수 가운데 가장 단순한 것을 고른다. 화면에서 직접 바꿀 수도 있다.
- 식의 기준점: x가 0에서 멀면(|평균| > 3×표준편차) 식을 `y = a + b·(x − x0) + …`, `a·e^(b·(x−x0))`, `a·(x/x0)^b` 꼴로 쓴다. 모델 JSON에 `x0`가 들어 있다.
- **95% 예측 범위**: `ŷ ± t(0.975, df) · σ · √(1 + bᵀ(UᵀU)⁻¹b)`. 변환한 공간에서 계산한 뒤 원래 단위로 되돌린다.
- **검증**: 시간 변화는 뒤쪽 20%, 항목 관계는 5개 중 1개를 숨기고 맞혀 본다. 숨긴 값의 오차(RMSE)와 예측 범위 안에 들어온 비율을 보여준다.
- **상세 통계** (`Regression.details(model)`): 계수별 표준오차·t·p값·95% 신뢰구간, 분산분석표(F 검정),
  AIC/BIC, 더빈-왓슨(자기상관), 자크-베라(정규성), 표준화 잔차(튀는 값), 지렛값·쿡의 거리(영향이 큰 값), 다중 회귀의 VIF(다중공선성).
  같은 데이터로 Python statsmodels와 비교했을 때 1e-9 이내로 일치한다 (테스트에 기준값 포함).
  지수·로그·거듭제곱은 직선으로 바꾼 공간(ln y 등)에서 검정한다.
- 다중 회귀는 함께 쓸 항목을 고를 수 있고, 시간(t)도 설명변수로 넣을 수 있다.
- 계산 안정성: 설명변수를 `u = (g − center) / scale`로 표준화해서 푼다. 3차 계수는 numpy와 1e-12 수준까지 일치한다.

## 배치(반복 작업)별 분석 (`batch.js`)

같은 작업을 여러 번 반복한 기록(배치·사이클·로트·회차·강번 …)을 서로 비교한다.

- **입력 모양** (자동 판별, 직접 선택 가능)
  - 파일(시트) 하나 = 배치 하나. 배치 이름은 파일 이름이나 파일 안의 배치 번호 칸 값. 이름의 숫자 순서(1, 2, …, 10)로 정렬
  - 배치 번호 칸이 있는 긴 표. 병합 셀처럼 첫 줄에만 번호가 있으면 아래로 채우고, "-"나 띄엄띄엄 나오는 "0" 같은 대기 표시는 뺀다.
    같은 배치가 여러 파일에 나뉘어 있으면 합친다
  - 열마다 배치 하나인 넓은 표("1차", "#2" 같은 이름도 됨, "No" 칸은 뺌)
  - 연속 기록: 값이 기준 아래로 일정 시간(기본: 2분과 측정 간격 3배 중 큰 값, 직접 입력 가능) 넘게 떨어지면 다음 배치.
    날짜가 있는 시각이면 하루 단위 파일을 이어 붙여 경계에 걸친 배치도 하나로 본다
- **값 종류**
  - 시간당 양(유량 Nm³/h, 전력 kW …): 총량 = 시간으로 적분. 이름에 /h·/min·/s·kW 같은 단위가 있으면 자동
  - 측정값(온도·압력·농도 …): 적분하지 않고 시간 가중 평균·최고값 등을 비교. 기본은 앞뒤를 자르지 않는다
- **비교할 값**: 총량·평균값(시간 가중)·최고값·끝 값·걸린 시간 중 선택.
- **작업 구간**: 바닥값 + (최대 − 바닥값)의 5%(조정 가능) 넘는 첫 시점 ~ 마지막 시점. 바닥값은 맨 아래에 평평하게 모인 점(대기 중 0점 오차)이 있으면 그 값, 없으면 0.
  최대는 세 번째로 큰 값(한 점이 튀어도 흔들리지 않게). 혼자 튀는 한 점은 이웃 평균으로 고치고 표시한다.
- **총량**: 사다리꼴 공식 `Σ (Qᵢ+Qᵢ₊₁)/2 × Δt ÷ 단위초(h=3600)`. 순시값의 산술평균은 측정 간격이 고르지 않으면 틀리고, 그대로는 총량도 아니다.
  값 칸 이름의 단위에서 총량 단위를 만든다(Nm3/h → Nm3, kW → kWh). 누적(적산)계 칸이 있으면 적분값과 비교한다.
- **시간 칸**: 날짜·시각 글자는 reader로 읽는다(최신순·자정 넘김 처리). 숫자 칸은 이름의 단위(초·분·시간·일)를 쓰고, 이름에 단위가 없으면 값 범위로 짐작해 알린다.
  초가 없는 시각(HH:MM)으로 같은 시각이 많으면 그 1분 안에 고르게 나눈다.
- **대표 곡선**: 공통 시간축(측정 간격, 최대 600칸)으로 보간한 뒤 시점마다 평균·중앙값·10/90%를 구한다.
  - 경과 시간 모드: 먼저 끝난 배치는 시간당 값이면 0, 측정값이면 빈 값 → 시간당 값의 평균 곡선을 적분하면 평균 총량과 같다
  - 진행률 모드: 배치마다 길이를 0~100%로 맞춘다
- **많이 다른 배치**: 다음 중 하나면 표시한다. "빼기"로 계산에서 뺄 수 있다(2개는 남아야 함).
  - 비교할 값·길이·곡선 모양의 강건 z(중앙값·MAD 기준, MAD = 0이면 평균 절대 편차)가 3 초과
  - 작업 중간 끊김, 기록 빠짐
- **중간 예측**: 길이 중앙값의 20~60% 시점까지의 값(총량이면 그때까지 적분, 최고값이면 그때까지 최고)으로 최종 값을 선형 예측한다.
  검증 오차(식에 쓰지 않은 배치로 잰 오차)를 같은 배치들의 표준편차와 비교한다.
- **배치 정보(조건)**: 줄마다 배치 하나인 표. 번호 칸(이름에 배치·강번·lot 등, 없으면 첫 칸)으로 짝짓는다(대소문자·공백·`.0`·앞자리 0 무시, 이름 안의 한 토막이 같아도 됨, 한 줄은 한 배치에만).
  - 항목별 상관·단순 회귀(p값)와 다중 회귀
  - 원단위(비교할 값 ÷ 항목): 생산량·원료량 같은 "양" 칸을 자동으로 고르고(온도·압력·% 제외) 화면에서 바꿀 수 있다
- **요약표 → 측정값 분석**: 배치별 요약표를 측정값 분석 모드로 넘겨 상세 회귀를 한다. 비교할 값으로 계산한 칸(원단위, 총량↔평균)은 설명 항목에서 뺀다.
- **엑셀**: 배치별 요약(통계 수식 포함) · 순시값(시간 정렬 행렬 + 평균/중앙값/10·90%) · 그래프 · 함수설명 · 원본 순시값.

## 수지(입·출·저장량) 분석 (`balance.js`)

저장소(탱크·홀더·사일로·배터리 …)의 유입·유출 계측값과 저장량(레벨)으로 **어느 계측기가 몇 % 틀리는지**, 계측 안 되는 손실이 얼마인지 찾는다.

- **입력**: 계열마다 시간축이 달라도 된다.
  - 시각 + 여러 칸 (글자 칸은 계열에서 뺌)
  - 시각·태그·값의 긴 표 (값 칸이 하나일 때만. 태그마다 따로 시간을 읽음)
  - 계열마다 다른 파일, 같은 칸으로 하루씩 나눈 파일(같은 이름 계열은 시간 순으로 이어 붙임)
  - 날짜 없이 시각만 있는 파일: 같은 모양 파일은 이름 순으로 하루씩 잇고, 다른 파일은 겹치는 시간이 가장 긴 쪽으로 맞춘 뒤 알린다
  - 숫자 시간 칸: 이름의 단위(초·분·시간·일), 엑셀 날짜 일련번호
- **역할**: 이름으로 추측하고 화면에서 바꿀 수 있다.
  - 회수·유입·투입 → 유입, 사용·소비·유출 → 유출, 레벨·수위·SOC → 저장 레벨, 저장량·부피 → 저장량, 온도·압력·% → 안 씀, 나머지 → 유출
  - 유량 단위: /h, /min, /s, /일, 배수 ×1000(kNm3/h, 천Nm3/h)
- **적분**: 유량은 구간 [a, b]마다 **자기 측정 시각 그대로** 사다리꼴 적분한다. 경계값은 보간한다. 레벨은 구간 경계에서 보간한다.
- **빈 구간 제외**: 유량은 빈틈이 max(측정 간격 3배, min(구간/10, 5분))보다 길면, 레벨은 측정 간격 3배보다 길면 그 구간을 쓰지 않는다.
  "사라진 양"과 누적 그래프도 빈틈 없는 구간만으로 계산한다.
- **수지 회귀**: 구간마다 `c·ΔL = Σ sᵢ·βᵢ·Fᵢ + a·Δt`.
  - c(레벨 1단위당 부피)를 알면: βᵢ와 a를 추정한다. 저장소가 여러 개면 저장량 변화를 더한다(레벨마다 c 필요).
  - c를 모르면: 레벨을 y에 두고 `ΔL = Σ gᵢ·sᵢ·Fᵢ + g₀`로 푼 뒤, 믿는 계측기 r을 기준으로 `c = 1/g_r`, `βᵢ = gᵢ/g_r`, `a = g₀/g_r`.
    신뢰구간은 계수 공분산으로 델타법. (예전 방식처럼 레벨을 x에 두면 레벨 잡음 때문에 c가 작게 나오고 맞는 계측기도 틀렸다고 나온다)
  - 구간마다 양이 일정한 계열(정지·고정 운전)은 β = 1로 두고 나머지를 계산한다.
- **판정** (허용 오차 기본 1%)
  - 데이터 확인: β가 0.7~1.3 밖이거나, 95% 범위 반폭이 20%보다 넓거나, 구간마다 양의 변동계수가 2% 미만
  - 편차 있음: p < 0.05이고 `|1/β − 1|` > 허용 오차
  - 정상: 95% 범위 전체가 [1/(1+허용), 1/(1−허용)] 안
  - 차이는 있지만 허용 범위 / 편차 없어 보임(범위 반폭 ≤ 3×허용) / 판단 불가
  - 환산값 의심: c를 넣었는데 모든 계측기가 같은 쪽으로 비슷하게 틀리면, 계측기보다 c가 틀렸다고 보고 자료로 본 c를 알려준다
- **레벨 지연**: 레벨이 하나면 ±5분 안에서 수지 차이가 가장 작아지는 시간 차이를 찾아, 20% 넘게 줄면 맞춰 계산하고 알린다.
- **구간 길이**: 자동이면 15분(측정 간격의 10배 이상, 구간 수 ≥ 계열 수 + 8). 절반·두 배로도 계산해 판정이 바뀌는 계열을 알린다.
- **잡음 수준**: 레벨 2차 차분으로 잡음을 어림해, 보정 후 남은 차이가 잡음 수준인지 알려준다.
- **엑셀**: 계열별 합계(보정계수 수정 가능 수식) · 순시값(공통 시간축) · 구간별 수지 · 그래프 · 함수설명.

## 엑셀 수식 검증 방법

LibreOffice는 기본 설정에서 xlsx를 열 때 **재계산하지 않는다**. 저장된 값을 그대로 보여주므로, 그냥 열어 비교하면 검증이 되지 않는다.
사용자 프로필에서 `org.openoffice.Office.Calc/Formula/Load/OOXMLRecalcMode = 0`(항상 재계산)으로 설정한 뒤
`soffice -env:UserInstallation=file:///경로 --headless --convert-to xlsx`로 변환한다. 그다음 앱이 미리 계산해 둔 값과 재계산 값을 비교한다.

## 운전 조작 판단 (`control.js`)

운전자가 감으로 하던 조작을 기록에서 배워 **규칙과 식으로 형식화**한다. 가스 운전 자동화의 출발점이 될 수 있다.

- **설정**: 조작 항목(MV: 밸브 개도·설정값 등), 판단 근거 항목, 추세 창(시간 길이 → 칸 수, 예: 5분), 조작으로 볼 최소 폭(비우면 자동)을 고른다.
- **시점 가정**: 상태(t−1)를 보고 조작(t)을 했다고 본다. 조작 결과가 상태에 섞이는 것(누수)을 막기 위해서다.
- **특징**: 각 근거 항목의 직전 값과 최근 추세(창만큼 전과의 차이), 현재 조작값을 쓴다.
  시각이 끊긴 곳(보통 간격의 3배 초과)에 걸친 줄은 쓰지 않는다. 값이 절반도 없는 근거 항목은 빼고 알린다.
- **조작으로 볼 최소 폭(데드밴드)**: max(잡음 수준 = |Δ|의 중앙값 + 4·MAD, 조작 폭 중앙값의 절반). 계기 잡음을 조작으로 세지 않기 위해서다.
- **판단 규칙**: 회귀 나무(깊이 3). 나눠서 줄어든 오차의 F 값이 12 이상일 때만 나눈다.
  잎의 결론은 평균 조작량이 아니라 **그 상황에서 조작한 비율**로 정한다(운전자는 대부분 그대로 두므로 평균은 0에 묻힌다).
  - 올림: 3번 이상, 비율 ≥ 50% 또는 (≥ 10%이고 잎 밖 비율의 2배 이상), 내림 비율의 3배 이상 → 조작 폭은 그때의 중앙값
  - 내림: 같은 규칙, 둘 다 아니면 유지
- **선형 식**: 다중 회귀에서 p > 0.05인 항을 하나씩 뺀다(단계적 제거). 겹치는 항목은 하나만 뺀다. 남은 항이 없으면 식 없음.
- **검증**: 시간 블록 교차검증. 기록을 4토막 내고 앞 토막들로 배워 바로 다음 토막을 맞힌다(최대 3번). 비교 기준은 "조작 안 함"이다.
  - 오차(RMSE), 방향(올림·내림·유지) 맞힘, 실제로 조작한 순간의 방향 맞힘, 규칙이 조작하라고 할 때 맞은 비율
  - `learned`: 실제 조작 방향 맞힘 ≥ 50% 또는 기준보다 오차 5% 이상 작음 → `true`. 검증 구간에 조작이 없으면 `null`(판정 보류)
- **이산 조작**: 값이 5개 이하(기동/정지, 운전 대수)면 추천을 그 값 중 하나로 맞춘다.
- **추천**: `Control.recommend(L, { inputs: { 이름: { now, before } }, mvNow }, { min, max, maxStep })`.
  한계를 넘으면 잘라내고 `clipped`로 알린다. 기록 범위를 벗어난 입력은 `outside`로 알린다.
- **한계와 주의**
  - 운전자의 실수와 습관도 그대로 배운다.
  - 기록에 없는 운전 영역에서는 믿을 수 없다.
  - 운전자가 표에 없는 정보(경보, 지시 등)로 판단했으면 배우지 못한다.
  - 피드백 때문에 상관관계가 실제 공정의 반응과 다를 수 있다.
  - 실제 제어에 연결하기 전에 운전 보조(추천)로 충분히 검증해야 한다.

| type | 식 | params |
|---|---|---|
| linear / quad / cubic | `a0 + a1·x + a2·x² + a3·x³` | `[a0, a1, …]` |

`Regression.deserialize(model)`이 이 둘을 모두 처리한다.
