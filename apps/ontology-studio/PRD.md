# PRD · 온톨로지 스튜디오

> 흩어진 파일(표·문서·ZIP)을 **개념(클래스)과 관계**로 정리하고, **3D로 탐색**하며, **AI가 근거를 대며 답할 수 있는 형태**로 내보내는 브라우저 앱.

- 상태: v0.1 (이 PR) — ✅ 표시는 이번에 구현됨, ⏭ 표시는 다음 단계
- 실행 환경: 정적 웹앱(GitHub Pages). 서버·로그인·API 키 없음. 모든 데이터는 기기 안(IndexedDB)에만 저장

---

## 1. 문제와 목표

| 문제 | 결과 |
|---|---|
| 데이터가 CSV·엑셀·노트·JSON 으로 흩어져 있고, 서로 어떻게 이어지는지 한눈에 안 보임 | 관계를 사람이 머릿속으로 맞춰야 함 |
| 표를 그대로 AI 에 붙이면 "어느 열이 무엇을 가리키는지" AI 가 추측함 | 환각, 잘못된 조인, 출처 없는 답 |
| 온톨로지 도구(Protégé 등)는 전문가용, 폰에서 못 씀 | 일반 사용자는 구조화를 포기 |

**목표**
1. 파일을 넣고 60초 안에 첫 3D 그래프를 본다 (자동 형식화 + 확인 1화면).
2. 색·모양만 보고 노드 종류와 관계 종류를 구분한다 (범례 상시 표시).
3. AI 에 넣었을 때 **스키마 → 사실 → 인용 ID** 구조로 들어가, AI 가 근거를 대며 답한다.

**비목표(v0.1)**: 다중 사용자 협업, 서버 저장, 대규모(10만+ 노드) 실시간 렌더링, PDF 본문 추출.

## 2. 사용자와 시나리오

- **폰으로 일하는 실무자**: 팀·프로젝트·고객 표를 ZIP 으로 넣고 "누가 어떤 프로젝트에 얽혀 있나"를 본 뒤, 주변 그래프만 Claude 에 붙여 보고서 초안을 받는다.
- **노트 사용자(옵시디언 등)**: 노트 묶음 ZIP 을 넣으면 `[[위키링크]]`·`#태그`가 그래프가 되고, 표 데이터의 같은 이름과 자동으로 이어진다.
- **연구·기획자**: 긴 글을 "AI로 추출하기"로 엔티티·관계 JSON 으로 바꿔 기존 그래프에 합치고, 품질 검사로 중복을 정리한다.

## 3. 용어 (쉬운 말)

| 용어 | 뜻 | 예 |
|---|---|---|
| 클래스(개념) | 데이터의 종류 | 사람, 팀, 프로젝트 |
| 엔티티 | 실제 하나하나의 대상(노드) | 김하늘, 플랫폼팀 |
| 관계 종류 | 연결의 의미(선 색) | 소속, 참여, 선행 |
| 속성 | 엔티티에 붙은 값 | 입사일 = 2019-03-04 |
| 도메인/레인지 | 관계의 출발·도착 클래스 규칙 | 참여: 사람 → 프로젝트 |
| 추론 | 규칙으로 계산한 숨은 관계 | 선행이 전이 관계면 A→B→C ⇒ A→C |

## 4. 기능 요구사항

### F1. 가져오기 ✅
- 형식: ZIP(1단계 중첩까지), CSV/TSV, XLSX(자체 경량 리더, 날짜 서식 셀 → ISO 날짜), JSON/JSONL, JSON-LD, Markdown/TXT, 이 앱의 백업 JSON. 그 밖의 파일은 이름·형식·크기만 담은 `파일` 노드로 남겨 **빠뜨리지 않음**.
- 인코딩: UTF-8 실패 시 **EUC-KR(CP949)** 로 재해석(한국어 엑셀 CSV 대응). ZIP 파일명도 CP949 복원.
- 입력 경로: 파일 선택(여러 개), 드래그&드롭, 글 붙여넣기(JSON/표/메모 자동 판별), 예시 데이터.
- 안전장치: 표당 2만 행, ZIP 당 3,000 파일 상한(경고 표시). `__MACOSX`·숨김 파일 무시.

### F2. 자동 형식화(스키마 추론) ✅
표 하나하나에 대해 아래 순서로 추측하고, **"2단계 · 형식화 확인"** 화면에서 열마다 근거(`자동: 값의 100%가 '팀'의 ID와 일치`)와 함께 보여준다.

1. **열 프로파일링**: 비어있지 않은 값 수, 고유 값 수, 유일성, 자료형(숫자·날짜·참/거짓·URL·이메일·글, 90% 이상 일치 기준), 다중값(`;`, `|`) 여부.
2. **ID 열**: 이름이 `id/코드/번호…` 이고 유일 → 아니면 `*_id` 꼴 유일 → 아니면 첫 열이 유일하면 채택. 없으면 행 번호.
3. **이름(표시) 열**: `name/이름/제목/…명` 패턴(단 `설명`·`*_id` 제외) → 아니면 고유도 80% 이상인 글 열.
4. **외래키(관계) 감지**: 각 열의 값 집합과 (이번에 가져오는 표 + **이미 프로젝트에 있는 클래스**)의 ID/이름 집합의 **겹침 비율**을 계산.
   - 기준 60% 이상, 열 이름이 대상 이름을 포함하면(`담당팀_id` ↔ `팀`) 30% 이상.
   - 숫자 열은 이름 힌트가 있고 대상 ID 도 숫자일 때만(나이·수량 오탐 방지).
   - 자기 참조 허용(`매니저_id` → 같은 `사람` 표).
5. **범주 승격**: 반복되는 짧은 글 값(고유 값 ≤30 이거나 행 대비 ≤20%, 반복률 ≥2배)과 태그형 다중값 열은 **별도 클래스의 노드**로 승격 → 같은 값을 가진 행들이 서로 이어짐(예: 도시, 직급, 기술).
6. **연결표(다대다) 감지**: 다른 표를 가리키는 열이 2개 이상이고 이름 열이 없으면 "한 행 = 관계 하나"로 해석, 나머지 열은 **관계 속성**(예: 참여.역할)으로.
7. **중첩 JSON**: 객체 배열은 표로, 안쪽 객체 배열은 부모와 이어진 하위 표로(관계 이름 = 키), 중첩 객체는 `a.b` 열로 평탄화.
8. **문서**: 파일명 = 노드 이름(옵시디언 관례). `[[링크]]`는 **전체 엔티티에서 같은 이름을 먼저 찾아** 연결(표의 "검색 개편" 프로젝트와 회의록이 자동 연결), 머리말 `키: [[값]]` 은 그 키 이름의 관계로.

**엔티티 동일성**: (클래스, 키)가 같으면 같은 엔티티로 합치고 속성은 새 값으로 갱신 → 같은 파일을 다시 넣어도 중복이 생기지 않음(멱등). 가리켰지만 원본이 없는 대상은 `내용 없음(stub)` 노드로 만들고, 나중에 원본이 들어오면 채워진다.

### F3. 데이터 모델 ✅
```
project { name, classes[], relTypes[], entities[], relations[], sources[] }
class    { id, name, color('slot:n'|'#hex'), shape?, description }
relType  { id, name, color, description, symmetric, transitive, inverseOf, domain, range }
entity   { id: '클래스-키'(사람이 읽을 수 있고 RDF/Cypher 안전), classId, key, label, props{}, src[], stub? }
relation { id: 'from|type|to'(자연키 → 중복 불가), typeId, from, to, props?, src? }
```
- 출처(provenance): 엔티티·관계마다 `파일#행번호` 를 남겨 AI 가 근거 위치까지 말할 수 있게 함.

### F4. 3D 시각화 ✅
- three.js + 3d-force-graph. three 관련 코드는 그래프 탭을 처음 열 때만 불러옴(첫 화면 가볍게).
- **색 규칙**(검증된 8색 팔레트, 라이트/다크 각각 단계 지정): 만든 순서대로 고정 배정 — 필터로 개수가 바뀌어도 색이 바뀌지 않음. 9번째부터는 새 색을 지어내지 않고 회색 + 범례 강조로 구분.
- **이중 부호화**: 3D 그래프는 모든 색이 서로 붙을 수 있는 형태라 색만으로는 안전한 구분이 3가지 수준 → 노드는 **색 + 모양(구·정육면체·팔면체·사면체·원기둥·도넛·십이면체·십자)**, 관계는 **색 + 범례 탭 강조 + 선 위 관계 이름표**.
- 범례 2줄(노드/관계) 상시 표시, 누르면 그 종류만 강조. 숨기기는 보기 설정에서.
- 노드 크기 = 연결 수, 방향 화살표(대칭 관계는 화살표 없음), 같은 두 노드 사이 여러 관계는 곡선으로 분리, 자기 참조는 고리.
- 노드 선택: 이웃 강조 + 관계 이름표 + 흐르는 입자(방향 표시) + 카메라 이동(아래 정보창에 가리지 않게 화면 중심 이동).
- **경로 찾기**: 두 노드 최단 경로(BFS, 숨긴 관계는 지나가지 않음) → 단계별 표시 → "이 경로를 AI 에게 묻기" 프롬프트 복사.
- 배치: 자유 / 개념별 묶기 / 연결 묶음별(라벨 전파 커뮤니티) / 계층(DAG) / 방사형. 순환이 있으면 안내.
- 성능 상한: 화면에 2,500 노드(연결 많은 순), 링크 2,500 초과 시 얇은 선으로 전환, 이름표는 중요 노드 24개 + 강조 대상만.
- 화면 PNG 저장.

### F5. 구조 편집(형식화 다듬기) ✅
- 클래스: 이름·정의·색·모양 변경, 합치기, 삭제, **속성 → 노드 승격**(예: 사람.도시 → 도시 노드).
- 관계 종류: 이름·정의·색, 도메인/레인지 규칙(실제 쓰임으로 자동 지정 버튼), 대칭·전이·역관계, 합치기, 삭제.
- 엔티티: 검색·필터, 추가/편집/삭제, 관계 추가(방향 선택, 새 관계 종류 즉석 생성).
- 모든 변경 **되돌리기(40단계)**.

### F6. 추론 ✅
- 대칭(A→B ⇒ B→A), 역관계(A 관리 B ⇒ B 피관리 A), 전이(A→B→C ⇒ A→C, 최대 5,000개).
- 저장하지 않고 **그때그때 계산**(원본 오염 없음), 그래프에서는 흐린 선, 내보내기에서는 `(추론)` 표시 + OWL 에는 `owl:SymmetricProperty` 등으로 선언.

### F7. 품질 검사 ✅
- 중복 후보: 정규화 이름 일치 + 같은 클래스 안 바이그램 Dice ≥ 0.85(오타·띄어쓰기) → 대표 선택 후 합치기(연결 이전, 자기고리 제거).
- 고립 노드, 내용 없는 stub, 도메인/레인지 위반, 한 관계가 3가지 이상 클래스 조합에 쓰임(의미 혼재), 정의 없는 클래스/관계.
- **AI 에게 정의 초안 받기**: 스키마+예시로 프롬프트 생성 → 답(JSON) 붙여넣기 → 빈 정의만 채움.

### F8. AI 내보내기 ✅ (이 앱의 핵심 가치)
설계 원칙 — AI 가 "추측"하지 않도록:
1. **스키마 먼저**: 클래스(개수·정의·속성 자료형) → 관계 종류(도메인→레인지·정의·대칭/전이 표시) → 사실.
2. **인용 가능한 ID**: 모든 엔티티를 `이름 [클래스-키]` 로 표기, 프롬프트에서 [ID] 인용을 요구.
3. **주어 기준 묶음**: 같은 주어의 사실을 한 덩어리로, 같은 관계의 대상은 한 줄로(토큰 절약 + 관계 방향 혼동 방지).
4. **범위 좁히기(검색 증강)**: 선택 노드의 1~3단계 이웃만(ego-graph) 내보내기 → 질문 관련 부분만 주어 정확도↑ 토큰↓.
5. **근거 고정 프롬프트**: `<instructions>/<knowledge_graph>/<question>` 구조, "그래프에 없음" 명시, 경로 표기, 추론 표시 요구.

| 형식 | 용도 |
|---|---|
| AI 컨텍스트(MD) — 읽기 좋게 / 압축 | 대화창에 붙여넣기, 압축은 `ID\|클래스\|이름\|속성` + `출발>관계>도착` 줄 형식 |
| 질문 프롬프트 | 위 + 지시문 + 질문(예시 질문 자동 제안) |
| JSON-LD | W3C 연결 데이터, `@context` 포함, 스키마 노드 포함 → 이 앱으로 왕복 가능 |
| RDF Turtle + OWL | Protégé·GraphDB 등 온톨로지 도구, 자료형(xsd:date/decimal) 지정 |
| 트리플 CSV | 지식그래프 임베딩·분석 |
| Cypher | Neo4j/Memgraph, `UNWIND` 500건 단위 배치 + 유일 제약 |
| 백업 JSON | 이 앱으로 교체/합치기 |

- 묶기 옵션: 개념별 / **연결 묶음별**(커뮤니티 단위로 관련 사실을 모아 AI 가 맥락을 덩어리로 이해).
- 글자 수·**토큰 추정**(영문 4자, 한글 1.5자 ≈ 1토큰 근사) 표시, 10만 토큰 초과 경고.
- 복사 / 파일 저장 / 휴대폰 공유 시트(파일로 바로 Claude 앱에 보내기).

### F9. AI 로 추출하기(사람-AI 루프) ✅
- API 키 없이: 원문 → **현재 스키마를 포함한 추출 프롬프트** 복사 → Claude 앱 → 답(JSON) 붙여넣기 → 검증 후 합치기.
- 기존 이름과 같은 엔티티는 자동으로 같은 노드로(이름 기반 동일성), 새 클래스/관계는 자동 생성. 코드펜스·앞뒤 설명 섞인 답도 처리.

### F10. 저장·개인정보 ✅
- IndexedDB 자동 저장(0.5초 디바운스), 실패 시 localStorage, 그것도 실패하면 알림 + 백업 내보내기 유도.
- 외부 전송 없음(폰트 CDN 제외). 공개 저장소에는 예시 데이터(가상)만.

|---|---|---|

## 6. 기술 구조

```
파일/ZIP ──▶ parse/ (csv·xlsx·json·markdown, 인코딩 판별)
                │  표(table) · 문서(doc) · 조각(fragment)
                ▼
          infer.js  proposeMappings → (사용자 확인) → buildFragment
                ▼
          model.js  mergeInto: 클래스/관계 이름으로 연결, (클래스,키) 동일성, stub 해소
                ▼
     project (IndexedDB) ──▶ graph.js  색인·추론·경로·커뮤니티
                 │                 ├─▶ graph3d.js  three.js 렌더(지연 로딩)
                 │                 ├─▶ quality.js  중복·규칙 위반
                 └─────────────────┴─▶ export.js   MD·프롬프트·JSON-LD·Turtle·CSV·Cypher
```
- React 19 + Vite, 상태는 단일 프로젝트 객체 + 순수 함수(`ops.*`)로만 변경 → 되돌리기가 단순 스냅샷.

## 7. 다음 단계 아이디어 (기술 로드맵)

### Phase 2 — 정확도와 규모
1. ⏭ **임베딩 기반 엔티티 해석**: 브라우저 내 다국어 임베딩(transformers.js + 소형 모델)으로 "삼성전자 ≈ Samsung Electronics" 같은 동의어 중복 탐지, 문서 속 언급 ↔ 엔티티 자동 연결.

3. ⏭ **PDF·DOCX 본문 추출**(pdf.js, mammoth) → AI 추출 루프로 바로 연결.
4. ⏭ **Web Worker + OPFS**: 해석·추론을 백그라운드로, 대용량은 OPFS 저장. 3D 는 InstancedMesh 로 5만 노드급 LOD.
5. ⏭ **중심성 지표**(PageRank·매개 중심성): 노드 크기 옵션, AI 컨텍스트 맨 앞에 "핵심 엔티티 Top 10" 요약.

### Phase 3 — 표준·연동
